Scope: everything except `/switch/playground/` and OS/retro mode (both being rebuilt; switch was never flipped).
Tested: dev server `localhost:5176` (shared, other agents editing) and a production build served by `vite preview` on :4176 (stopped, `dist/` removed afterwards). Chromium via Playwright 1.64.1, 1440x900 unless stated. Scripts are in `C:/Users/ashut/AppData/Local/Temp/verify-v1/`. Screenshots in `D:/Coding/ash-portfolio/.research/verify/v1/`.

Verdict: no blockers. 3 majors (keyboard focus not scrolled into view on home, CLS over 0.1, LCP over 4s on localhost). The rest is minor.

## 1. Route loads

Dev and prod, every route: HTTP 200, `phase=idle`, no `data-busy`, exactly 1 `.curtain`, exactly 1 `h1`, correct `document.title`.
Routes: `/`, `/work/`, `/about/`, `/contact/`, all 16 `/work/<slug>/`, bogus path. Console errors/warnings: 0. `pageerror`: 0. `requestfailed`: 0. Non-2xx: 0 (the only 404 in the logs was my own probe import of `/src/core/motion.ts` against the prod build).
Prod HTML (curl-equivalent fetch, before any JS): every route contains its content `h1` and title; `/switch/work/<slug>/` HTML is 12.7 to 17.9 KB with 2 to 6 media refs each. `404.html` contains the 404 h1. Media: images and videos in the HTML resolve (`/switch/media/...` 200, `image/jpeg` and `video/mp4`), 0 broken images and 0 video errors after scrolling home, work, shopstr, verbx. 0 images without `alt`.

## 2. Client navigation (dev and prod identical)

All assertions passed after settle (path, scrollY 0 for non-case pages, 1 curtain, 0 `.curtain-flip`, `data-busy` cleared, `phase=idle`, title, 1 h1):
header nav to Work / About / Contact, brand mark to home, home Selected Work to case, Work index row to case, case Next, Back x2 and Forward x2 across them, double-click on nav during a transition (second click ignored, lands on first target).
Timings click to idle: 1675 to 1845ms for nav, 1780 to 2195ms with a thumb (target about 2.4s), 847 to 1115ms for back/forward (target 0.9s), 693ms under reduced motion. Only failure: finding 4.

## 5. Keyboard

- Home tab order: skip link, brand, Work, Playground, About, Contact, switch, 5 Selected Work links, "full index", Let's talk, email, X, LinkedIn, Behance, GitHub, Back to top. Every stop has a visible 2px cobalt outline (`rgb(44,51,245)`), except Work index rows, which signal focus by dimming the other rows, underlining the title and showing the cover (`kbd-work-row-focus.png`; verified OK). Order matches reading order. Problem: finding 1.
- Work index: skip link, header, 6 filter buttons (70 to 157px wide, 34px tall), then 16 rows.
- Skip link: Enter moves focus to `main`, URL `#main`. OK.
- Header switch: reachable (7th stop on every page), `role="switch"`, `aria-checked="false"`, name "1998 mode", 64x28 hit target, 2px focus ring. Space/Enter toggling NOT tested (OS mode out of scope).
- Escape: closes the mobile menu and restores focus to the Menu button. Playground drawers not tested (out of scope).
- Header hides on scroll down and reappears on scroll up; it is correctly not clickable while hidden, so scripts must scroll up first.
